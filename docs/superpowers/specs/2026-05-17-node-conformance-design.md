# Node Conformance Testing — Design

**Status**: Draft
**Date**: 2026-05-17
**Author**: Indy Jones
**Related**: `docs/CONFORMANCE.md`, [Kubernetes node-conformance docs](https://kubernetes.io/docs/setup/best-practices/node-conformance/)

## Problem

Rusternetes' only conformance signal is the full Sonobuoy v1.35 suite (441 tests, ~hours per run). It needs the whole cluster up (api-server + scheduler + controller-manager + 2 kubelets + kube-proxy + CoreDNS) and exercises every component at once. When a test fails the source can be any of them.

Result: long iteration cycles, noisy attribution. Round-to-round regressions (e.g., Round 107→108 dropped from 96% to 60%) take days to pinpoint.

## Goal

Add a kubelet-scoped conformance loop that:

- runs against a single kubelet without scheduler / controller-manager / kube-proxy
- finishes in minutes, not hours
- isolates kubelet-only regressions (pod lifecycle, volumes, probes, security context, resource limits)
- complements (not replaces) the full Sonobuoy suite
- produces a tracked pass/fail/skip number in `docs/NODE_CONFORMANCE.md` analogous to the existing CONFORMANCE.md ledger

## Non-goals

- Full CRI implementation (we are bollard-direct; no kubelet shim)
- RBAC on the kubelet HTTP port (test-only surface, single-node scope)
- Replacing Sonobuoy — that stays as the certified-conformance source of truth
- cAdvisor parity — only the `/stats/summary` fields ginkgo asserts on

## Architecture

Two new artefacts plus one new kubelet module.

```
┌──────────────────────────────┐
│ scripts/run-node-conformance │
│   .sh                        │
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐      ┌────────────────────────┐
│ compose.node-conformance.yml │─────▶│ api-server :6443       │
│ (api-server + 1 kubelet)     │      └────────────────────────┘
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐      ┌────────────────────────┐
│ kubelet (node-1)             │◀────▶│ e2e_node.test (ginkgo) │
│   :10250 server.rs           │      │  --focus=               │
│   - /pods                    │      │  '\[NodeConformance\]'  │
│   - /healthz                 │      └────────────────────────┘
│   - /stats/summary           │
│   - /runningpods/            │                │
│   - /exec, /logs alias       │                ▼
└──────────────────────────────┘      /tmp/node-conformance/
                                       results.json + ginkgo log
```

### Component 1 — `crates/kubelet/src/server.rs`

New axum router bound on `:10250` (TLS, client-cert auth against api-server CA).

| Route | Method | Purpose |
|-------|--------|---------|
| `/pods` | GET | Pods bound to this node from storage (filter `spec.nodeName`) |
| `/runningpods/` | GET | Subset of `/pods` whose containers report Running via bollard inspect |
| `/healthz` | GET | 200 if last `sync_loop` tick within `2 × sync_interval`, else 500 |
| `/stats/summary` | GET | Minimal cAdvisor-shape JSON: node CPU/mem + per-pod CPU/mem, sourced from existing metrics |
| `/exec/:pod/:ns/:container` | POST | Alias to current `/exec/:container_id` handler |
| `/logs/:pod/:ns/:container` | GET | Proxy to api-server's existing log endpoint |

Reuses `.rusternetes/certs/kubelet.{crt,key}` already generated by `scripts/generate-certs.sh`. AuthN: TLS client-cert verified against api-server CA. No RBAC (single-node scope, test-only).

Lives behind a feature flag — only enabled by `compose.node-conformance.yml`. Default compose files keep current `:metrics_bind_port` behaviour.

### Component 2 — `compose.node-conformance.yml`

Strips down `compose.yml`:

- etcd
- api-server
- one kubelet (`node-1`)

Omits scheduler, controller-manager, second kubelet, kube-proxy, CoreDNS. Kubelet given `RUSTERNETES_KUBELET_SERVER_PORT=10250` env to opt into the new server.

### Component 3 — `scripts/run-node-conformance.sh`

Mirrors `scripts/run-conformance.sh` shape:

1. Bring up `compose.node-conformance.yml`
2. Wait for kubelet `:10250/healthz` to return 200
3. Download `kubernetes-test-linux-amd64.tar.gz` for v1.35 if not cached, extract `kubernetes/test/bin/e2e_node.test` and `ginkgo` to `.bin/`
4. Run `ginkgo --focus='\[NodeConformance\]' .bin/e2e_node.test -- --node-name=node-1 --kubelet-host=localhost --kubelet-port=10250 --kubeconfig=~/.kube/rusternetes-config`
5. Dump results to `/tmp/node-conformance/`
6. Parse pass/fail/skip counts and append a row to `docs/NODE_CONFORMANCE.md`

Accepts optional `--focus` override for narrowing during debugging.

### Component 4 — `docs/NODE_CONFORMANCE.md`

Same shape as CONFORMANCE.md ledger:

```
| Round | Date | Pass | Fail | Skip | Pass Rate | Notes |
```

Plus a "Currently skipped because we lack X" section listing endpoints / features the harness depends on.

### Component 5 — `scripts/node-conformance-progress.sh`

Mirror of `scripts/conformance-progress.sh` — tails ginkgo output, prints running pass/fail counters.

## Phases (delivery)

| PR | Scope | Outcome |
|----|-------|---------|
| **PR1 — Probe + scaffold** | compose file, run-script, doc skeleton, fetch upstream binary | Baseline number (most tests fail/skip; that is fine) |
| **PR2 — Kubelet HTTP surface** | `crates/kubelet/src/server.rs` with all 6 routes, unit tests, integration test | Number jumps once endpoints exist |
| **PR3 — CI hook + progress script** | optional `.github/workflows/node-conformance.yml` (self-hosted), `node-conformance-progress.sh` | One-command per-PR signal |

Each PR is independently mergeable. PR1 alone is useful (catalogs what's missing).

## Data flow

```
ginkgo (e2e_node.test)
  │
  ├─ HTTPS :10250 ─▶ kubelet server.rs ─▶ storage / bollard
  ├─ HTTPS :6443  ─▶ api-server          (create test pods, watch status)
  └─ stdout/json  ─▶ /tmp/node-conformance/results.json
```

## Error handling

- Script: `set -euo pipefail`; non-zero exit if compose-up or healthz wait fails
- Per-test ginkgo failures are non-fatal to the script (counts get recorded, script exits 0)
- Kubelet handlers return Kubernetes-shaped `Status` errors via existing `common::Error::IntoResponse`
- Missing certs: script fails fast with pointer to `scripts/generate-certs.sh`

## Testing

- Each new handler in `server.rs`: unit test using `axum::Router::oneshot` + `MemoryStorage`, asserting status code + JSON shape
- Integration: bring up `compose.node-conformance.yml`, curl each endpoint with the kubelet client cert, assert shape
- Smoke: `bash scripts/run-node-conformance.sh --focus='Conformance.*pod.*single.container'` — finishes in <60s, must pass at least one test by end of PR2

## YAGNI cuts

- No RBAC on kubelet :10250
- No exec streaming protocol changes (existing handler is good enough for ginkgo's smoke checks)
- No GA cAdvisor metrics — only the subset ginkgo reads
- No CRI shim
- No second-kubelet support — single-node by design

## Open questions

None resolved at design time; user opted to skip clarifying-question phase. Items deferred to implementation:

- Exact v1.35 test binary URL / checksum pinning
- Whether to vendor `e2e_node.test` in `.bin/` or fetch on each run (likely fetch + cache by sha256)
- Where to gate the new kubelet server module — feature flag vs env var (likely env var, matches existing config style)
